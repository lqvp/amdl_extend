Read-only, and deliberately so: destructive cleanup of the library is refused outright, because a file operation run by mistake against 341 GB of real data is a far larger harm than the convenience of offering it. This page is the list. The per-root count and the *empty* warning below it are the part that matters, and `degraded_roots` cannot cover them: a drive that is not plugged in can be mounted and empty rather than missing -- Docker's bind-mount autocreate makes the directory -- and that reads as a perfectly healthy root with nothing in it. Nothing on disk distinguishes an empty library from an absent drive, so the only honest thing is to show the count and let a human notice a zero. Without it the failure is a silent re-download of everything that lived on the drive. The path column is `album.path`, not `album.relpath`: a bare relpath does not resolve once more than one library root is configured -- it says which directory but not which library -- and in a listing that matters as much as it does in a `skip_reason`. It is the same `roots[root_index] / relpath` expression the API builds. The filter is progressive: it is an input plus a script that hides rows, so the page is the full listing with scripting off and a searchable one with it.
